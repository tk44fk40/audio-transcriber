# 自律的コード実装 ＆ 品質保証ワークフロー (`autonomous-code-workflow`)

短文指示を受け、以下の 7 段階自律ワークフローを順次実施

## ワークフロー手順

### Step 0: Issue ・ ブランチ ＆ 計画準備
1. **GitHub Issue 作成**: 指示された場合は、タスクリスト（`- [ ] タスク名`）付き Issue を作成 (`gh issue create`)。
2. **Issue 連動ブランチ**: 指示された場合は、`issue-<Issue番号>/<機能名>` ブランチを作成・チェックアウト
3. **計画書追記**: `implementation_plan.md` / `task.md` に関連 Issue, 作業ブランチ名を明記
4. **計画承認**: 計画書の作成・更新後、ユーザーの計画承認を得る

### Step 1: インターフェース（シグネチャ・型）の優先提示と合意
内部実装前に骨組み（スタブ）のみを提示し、ユーザーと型合意を得ること（`Any` 排除）
- 関数シグネチャ（関数名, 引数型, 戻り値型）
- Google スタイル Docstring (サマリー行, `Args`, `Returns`, `Raises`)
- シグネチャ提示後、ユーザーの明示的な合意を得てから Step 2 へ進む

### Step 2: TDD (テスト駆動) 単体テストの先行作成
合意後、実装前に `tests/test_*.py` で単体テストを作成または編集：
- モジュール分割 ＆ AAA パターン (Arrange-Act-Assert) 徹底
- テスト内容について辛口で評価し、改善点があれば自律的に修正と評価を繰り返す
  - テスト内容は対象機能に対して妥当か
  - カバレッジ目的の身のないテストになっていないか
  - 境界値などの検討は十分か
  - 可読性の高いわかりやすいテストになっているか

### Step 3: アトミック（小単位）実装
- `AGENTS.md` の規模制限 & 可読性 (KISS原則)に準拠し、小単位で実装コードを作成

### Step 4: ローカル一括自動検証 (`pre-commit`)
ユーザーへ提示前に `pre-commit` で検証：
- **検証コマンド**: `uv run pre-commit run --all-files -v`
- **局所テスト・全体検証の使い分け**:
  - **TDDサイクル / 局所デバッグ時**: 高速にイテレーションを回すため、対象テストのみを個別実行（例: `uv run pytest -v --no-header tests/test_xxx.py`）
  - **コミット前 / 全体検証時**: `uv run pre-commit run --all-files -v` で、静的解析・型チェック・全件テスト・カバレッジ出力を検証

### Step 5: セルフチェック ＆ エビデンスログ提示
コードの作成・修正後に以下の観点でセルフチェックを実施
（パスするまで自律的に再修正）
- **セルフチェック観点**:
  1. 開発ルール適合性
  2. 要件適合性
  3. 設計整合性
  4. 疎結合性
  5. テスト妥当性・網羅性（対象機能に対するテスト内容妥当性、エッジケースカバー,未カバー妥当性）
  6. 簡潔性 (KISS)
  7. 副作用
  8. パフォーマンス
  9. ドキュメント同期
- **ログ提示**:
  - TDDサイクル / アトミック実装 / 局所デバッグ時: 対象テストの合否ログ
  - コミット前 / 全体検証時: 全テスト ＋ カバレッジ表
- **未カバーナレッジ**: 未カバー箇所についてナレッジ(docs/testing_and_coverage.md)に反映・更新


### Step 6: PR 作成・マージ
指示された場合は、PR を作成して MAIN ブランチへスカッシュマージ
1. **PR 作成**: 本文に `Closes #<Issue番号>` を明記 (`gh pr create`)
2. **計画書更新**: 計画書 / `task.md` に PR 番号/URL を追記
3. **スカッシュマージ**: `gh pr merge --squash`
